# 三类简历筛选 Skills 质量修正审计（2026-08-18，v3）

## 目标与范围

本轮覆盖三个 Skill：AI 产品经理、高级全栈工程师、全栈开发实习生。目标是减少无依据拔高、把“未写”误判为“不满足”、来源冲突绕过二审、低置信证据直接触发方向性建议，以及模型伪造人工终态等错误。

本轮没有历史录用/绩效标签或招聘者双人盲标真值，因此不报告虚构的准确率百分比。当前可验证的是规则一致性、错误路径被阻断和代表性边界案例的回归结果；实际精确率、召回率和人工推翻率仍需在合法、去标识化的标注集上测量。

## 已修正的主要缺陷

| 缺陷 | 可能造成的错误 | 修正 |
|---|---|---|
| AI 产品经理记录可追加任意 criterion | 用学校/公司声望等自造维度影响建议 | 只允许固定八维且恰好各一次 |
| AI 产品经理 `E1` 可没有原文与位置 | 把模型臆测当成弱证据 | `E1`–`E3` 均强制最短摘录与位置 |
| AI 产品经理默认接受 `human_finalized`，且 `non_final` 可填写人工字段 | 模型输出伪装成人工完成记录 | 人工终态必须显式校验；非最终人工字段必须为空 |
| 两类全栈把来源冲突和直接反证都写成 `conflicting` | 来源矛盾可能直接触发负面建议 | `conflicting` 固定触发 `U03` 二审；新增 `directly_not_met` 表示可定位直接反证 |
| 方向性门禁可依赖 `low` 置信度证据 | 解析/归类不可靠时误推进或误淘汰 | 直接推进和负面门禁均拒绝低置信决策证据并要求二审 |
| 两类全栈未处理简历内提示注入/外部操作诱导 | 简历内容改变规则或诱导访问外链 | 新增 `U11_UNTRUSTED_CONTENT`，忽略指令并优先独立二审 |
| 两类全栈输出可混入电话、邮箱、身份证号 | 无关个人信息污染证据与人工判断 | 校验器递归扫描并拒绝直接标识符 |
| 两类全栈同人分时二审没有时间证据 | 同一次判断可被误记为两次独立复核 | Schema 1.2 要求带时区的一审/二审时间并校验先后顺序 |
| 输出版本更新缺少兼容窗口 | 新旧记录混配后静默产生不同语义 | 固定 schema/rubric 兼容矩阵并迁移新写入端 |

## 合同兼容矩阵

| Skill | 旧记录只读兼容 | 新记录写入 | 收缩条件 |
|---|---|---|---|
| 高级全栈 | `schema 1.1 + rubric v2` | `schema 1.2 + rubric v3` | 确认没有需保留的 v2 留档后移除旧组合 |
| 全栈实习生 | `schema 1.1 + rubric v2` | `schema 1.2 + rubric v3` | 确认没有需保留的 v2 留档后移除旧组合 |
| AI 产品经理 | `schema 1.2 + rubric v2` | `schema 1.2 + rubric v3` | 确认没有需保留的 v2 留档后移除旧 rubric |

版本不能交叉混配。`directly_not_met` 只允许在两类全栈的 schema 1.2 中生成。旧记录中的 `conflicting` 若没有 `U03`，应人工检查：来源事实矛盾则转二审；可定位直接反证则迁移为 1.2 的 `directly_not_met`。

## 回归场景

自动测试覆盖：额外 criterion、E1 无定位、默认伪造人工终态、非最终记录填写人工字段、旧/新版本兼容与混配拒绝、来源冲突绕过二审、直接反证、低置信推进与负面门禁、相邻技术迁移、实习生碎片化项目证据、提示注入、PII、二审模式、盲审、人工分歧和批量渲染。

这些测试只证明策略门禁按预期执行，不等同于真实简历上的统计准确率。

## 下一轮数据校准

每类岗位准备至少 10–20 份合法取得、去标识化、与验收集分离的简历，由招聘负责人和用人经理按当前 JD 独立盲标。至少记录：criterion 证据状态/强度、方向建议、分歧原因、面试后反证和人工最终处理。重点观察负面建议人工推翻率、强候选误入二审/暂不推进、弱候选误推进、`U03/U05/U06` 占比和证据定位错误率，再决定是否收缩 v2 兼容或调整 v3 门槛。
