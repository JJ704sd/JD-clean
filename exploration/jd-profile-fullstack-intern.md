## 2. 岗位成功画像

该岗位重点识别可培养的全栈工程潜力，而不是用高级工程师标准筛选学生：

1. 至少能用一种后端语言完成基础接口；
2. 理解 HTTP、REST、数据库和基础 SQL；
3. 具备 HTML/CSS/JavaScript 基础，Vue3 或 TypeScript 为优先信号；
4. 能在项目中学习、调试、测试、联调、部署或沉淀文档；
5. 对大模型 API、向量检索和 RAG 有兴趣并愿意学习；
6. 能接受指导，并逐步形成跨业务、前端、后端与算法的协作能力。

## 4. 项目证据等价规则

以下经历都可作为有效工程证据，不因缺少正式实习而降级：

- 课程设计；
- 校内项目；
- 个人项目；
- 社团或团队项目；
- 开源贡献；
- 黑客松、编程比赛中的实际工程产出；
- 实习经历。

判断重点是候选人的个人动作、问题难度、调试过程、完成度和学习结果，而不是项目来源的名气。

## 5. 加分项

1. 实际开发经历；
2. 技术博客或 GitHub 活跃记录；
3. Docker、Linux 或常用 Git 工作流；
4. 物流、供应链或电商项目/实习；
5. 算法竞赛、黑客松或编程比赛获奖。

加分项缺失不扣分。比赛奖项只能作为学习和问题解决线索，不能替代全栈项目证据。GitHub 仅在候选人主动提供且与筛选目的相关时查看。

## 6. 证据强度

| 级别 | 定义 | 招聘用途 |
|---|---|---|
| `E0` | 没有相关信息 | 记为“未提供证据”，不等于不会 |
| `E1` | 课程、技能列表或自评 | 生成基础验证题 |
| `E2` | 有项目上下文和可区分的个人实现 | 可支持核心基础能力 |
| `E3` | 有清晰问题、调试/取舍、完成结果和复盘 | 实习岗位的强潜力信号 |

实习生不要求生产规模。一个范围小但真正完成、能清晰解释的项目，可能比大型团队项目中的模糊参与更有价值。

## 7. 初步处置逻辑

- `advance_pending_human`：至少一种后端语言、Web/前端/数据基础和完整项目有可验证证据，或有明显学习潜力；仍须招聘者一审。
- `second_review`：行政条件未写、项目个人贡献不清、基础证据分散、AI 兴趣未体现、简历格式抽取不可靠或位于推进边界。
- `do_not_advance_pending_human`：简历明确没有可验证的编程/项目基础且与岗位核心要求差距明显时，可给出非最终建议，但必须由人确认。

不得因没有正式实习、学校品牌普通、项目包装不精美或没有竞赛奖项而给出负面结论。

## 8. 岗位专属二审触发器

1. 在读状态、专业或每周 4 天可用性未写；
2. 有后端语言关键词但没有实际项目上下文；
3. 没有正式实习，但课程/个人/开源项目显示较强完整交付；
4. 项目为团队成果，个人贡献无法区分；
5. Vue3、TypeScript、Redis 或 AI 经历缺失，但其他基础和学习证据较强；
6. 学校、年级、比赛或 GitHub 品牌可能影响了判断；
7. 候选人更接近初级正式工程师或其他方向，存在岗位归类不确定性；
8. 简历排版、OCR 或语言问题可能造成证据遗漏。

## 9. 正式冻结前需招聘负责人确认

1. “大三、大四或研二优先”是否保留，以及是否存在未写出的最低实习时长；
2. 本科在读与计算机专业是否允许等价专业或自学经历；
3. 每周 4 天是绝对条件还是可协商条件；
4. Vue3、TypeScript、Redis 和既有 AI 项目分别是加分、优先还是必须；
5. 课程项目是否需要代码链接、演示或作业验证；
6. 转正机会是否需要在筛选中识别长期意愿，以及该信息应在哪个阶段收集。
