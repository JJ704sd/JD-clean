## 2. 岗位成功画像

该岗位不是“前后端关键词都出现”即可，而是能够在跨境物流核心业务中承担全栈交付：

1. 使用 Go 或 Node.js 建设 BFF 和部分微服务；
2. 使用 Vue3、TypeScript、Vite 独立完成中后台页面；
3. 与算法工程师协作，把大模型、向量检索、RAG 或推理结果接入可靠业务链路；
4. 参与系统重构、计算密集型场景优化和扩展性建设；
5. 对微服务、前端工程化和 AI 工程化持续学习并推动演进。

## 4. 加分项

加分项只能在核心要求判断之后使用，缺失不扣分：

1. 物流或供应链系统经历；
2. 服务发现、熔断、限流等微服务治理落地；
3. Kubernetes 或 Docker Compose 部署；
4. 同时掌握 Go 和 Node.js，或用 Node.js 对接过 AI 能力；
5. 技术博客或开源贡献。

博客、GitHub 和开源内容只有在简历合法提供链接、且与岗位证据相关时才可使用；不得无限扩展搜索候选人的网络信息。

## 5. 证据强度

| 级别 | 定义 | 招聘用途 |
|---|---|---|
| `E0` | 没有相关信息 | 只能记为“未提供证据” |
| `E1` | 技能列表、自评或孤立关键词 | 生成验证问题，不能证明胜任 |
| `E2` | 有项目上下文、个人动作和责任边界 | 可作为核心要求的初步支持 |
| `E3` | 有复杂约束、取舍、生产结果或可量化影响 | 高级岗位的强信号 |

核心技术要求通常至少需要 `E2` 才能标记为 `supported`；“高级程度”不能仅凭年限和头衔，宜结合多个 `E3` 信号由人判断。

## 6. 初步处置逻辑

- `advance_pending_human`：核心要求大多有 `E2+` 证据，没有未解决冲突；招聘者仍须一审确认。
- `second_review`：任何核心要求属于“未提供证据”但可能改变结果，或存在技术迁移、个人贡献、工作年限、AI 经历、Vue 独立程度等不确定性。
- `do_not_advance_pending_human`：简历明确显示多个核心要求不匹配时可给出非最终负面建议，但必须列出直接证据并由招聘者确认，不能自动拒绝。

加分项不能弥补明确缺失的核心能力，也不能用单一综合分覆盖证据缺口。

## 7. 岗位专属二审触发器

1. 3 年开发或 1 年全栈的计算受日期重叠、兼职/实习或职责含糊影响；
2. 只有 Java/Python 等相邻后端栈，但有较强微服务、BFF 或重构证据；
3. 只写 Vue，无法确认 Vue3、TypeScript、Vite 或独立开发程度；
4. MySQL/Redis/Kafka 中某项缺失，但存在等价数据库、缓存或消息队列证据；
5. 简历未写 AI/RAG 经历，但其他工程能力很强；
6. 团队成果与候选人个人贡献无法区分；
7. “高级”主要由头衔和年限支撑，缺少生产复杂度、取舍或影响证据；
8. 缺口表中的“数据工程”目标与 JD 正文冲突影响判断。

## 8. 正式冻结前需招聘负责人确认

1. 3 年开发和 1 年全栈是否允许等价能力替代；
2. 学历与计算机专业是否为不可替代条件，相关等价经历如何处理；
3. Kafka、Vue3/TypeScript/Vite 是否要求逐项命中，还是接受同类技术迁移；
4. AI/RAG 经验是入职前硬要求，还是强工程能力加可培养性即可；
5. 缺口表“数据工程能力”是否为错误字段；
6. 对“高级”的最低生产规模、架构责任和技术影响如何定义。
