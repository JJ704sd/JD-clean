# AI 产品经理 prompt v3 迁移

## 原因

真实小样的模型响应已完成，但因 `criterion_name` 与固定名称不完全一致、面试追问少于 3 条而整份进入人工审核。证据内容与管理性输出字段耦合，降低了批量稳定性。

## 兼容矩阵

| 提示版本 | 模型输出 | Python 读取方式 | 状态 |
|---|---|---|---|
| `resume-screening-prompt-2026-09-01-v2` | 完整 AI 产品经理记录 | 忽略模型生成的结论和流程字段，按证据重新组装 | 既有未完成队列兼容 |
| `resume-screening-prompt-2026-09-01-v3` | `evidence`、`uncertainties`、`interview_probes` | Python 生成完整 Schema 1.2 记录 | 新任务默认 |

`prompt_version` 仍包含在 SQLite 任务键中，新任务不会覆盖旧任务。模型只负责一份简历的证据提取；Python 固定八个指标名称、补足 3～6 个针对性追问，并生成建议、摘要、人审门禁、分数和档位。

已完成但不合法的 v2 响应仍保留人工审核，不自动重试。尚未调用模型的 v2 任务可继续运行，系统会按记录中的 v2 生成原提示词，再由新的 Python 组装器处理响应。

## 回退

保留旧数据库和输出目录即可回看历史结果。若 v3 小样出现新的结构错误，停止批次且不要重试已完成响应；修正规则后升级提示版本并重新登记受影响来源。
