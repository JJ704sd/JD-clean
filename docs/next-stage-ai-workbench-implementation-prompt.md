# ResumeDesk 下一阶段实施操作提示词

下面整段文字可直接作为实现任务的提示词。它引用 [next-stage-ai-workbench-spec.md](next-stage-ai-workbench-spec.md)，自身不代表任何功能已经完成。

```text
在当前 ResumeDesk 仓库中实施 docs/next-stage-ai-workbench-spec.md，目标是下一 Windows 11 x64 内部预览版。现有 0.2.0-preview、提交 42470de 及其 Windows 产物是状态基线，不要把规格中的待实现能力描述为已交付，也不要生成或声称已验证 macOS 包。

开始前必须完整阅读适用的 AGENTS.md、docs/next-stage-ai-workbench-spec.md、docs/one-click-app-spec.md、docs/no-api-fallback-spec.md、docs/desktop-validation.md、docs/desktop-user-guide.md，以及相关 desktop、store、model、build 和测试代码。检查当前分支、暂存区和工作区，保留 output docs/、tmp/ 及其他无关改动；不得 reset、checkout 丢弃或覆盖用户工作。

先运行并记录最小基线：

    uv run --locked python -m unittest discover -s tests

若失败，先判断是既有失败还是环境/调用方式问题；不要把未通过检查描述为通过。实现应采用小步、可回退的方式，并按以下顺序推进：

1. 建立应用版本的单一来源，使 Python 包元数据、界面、诊断、构建文件名和 manifest 一致。目标版本只有在全部交付门槛满足后才切换为 0.3.0-preview；开发途中不得生成冒充已验收的发布包。
2. 设计并实现桌面数据库从 schema v1 到下一版本的显式迁移。迁移前自动备份，失败自动回滚；不得删除数据库重新初始化。新增 AI 批次、版本化不可变 AI 结果、人工修订关联、导入批次报告、软删除与 7 天回收区所需的最小字段或表。
3. 先完成数据生命周期：单份删除、恢复、立即永久清除、清空全部本地数据，以及独立的系统凭据清除。删除必须覆盖应用管理的原始副本、提取文本、草稿、人工修订和 AI 输出关联；不得暗示同时删除飞书或供应商侧数据。
4. 增加可见的人工修订时间线和完整审计导出。AI 原始结果保持只读，人工结论作为独立修订保存；旧修订查看不得覆盖当前草稿。
5. 重构材料页为单窗口批量工作台：空数据时显示导入→解析/OCR→批量 AI→人工确认→导出的引导；增加导入预览、可选递归、逐文件报告、已选数量、统一忙碌态和 n/N 进度。已有无 API 工作流必须始终可用。
6. 实现版本化 AI 输出合同。LLM 负责逐项事实/证据、缺失、冲突、风险、建议、追问和不确定性原因；Python 继续校验证据并计算确定性评分/档位。无法定位的引用不得计分，合同错误进入人工核对且不得自动追加付费修复请求。
7. 在材料主列表增加独立的 AI 状态、档位/建议、主要风险和人工状态，支持排序和筛选。AI 结果只能影响工作优先级，不得自动推进或淘汰候选人。
8. 简化模型设置：默认显示服务、模型和 Key，把 Base URL 等放入高级设置；保留 HTTPS 校验、禁止重定向携带凭据、/models 获取和手工模型名。分别显示未配置、连接可用、真实调用已验证、岗位已校准，不得把连接测试当作质量验证。
9. 完成搜索、键盘焦点和快捷键、125%/150% DPI、1366×768 适配。至少提供导入、搜索、保存、导出和页签切换的键盘路径。
10. 为所有新增行为编写或更新针对稳定公开 seam 的测试。至少覆盖迁移成功/失败回滚、软删除/恢复/到期清除、凭据清除、AI/人工隔离、批次停止、重复计费提示、导入报告、非 UTF-8 待确认、修订历史和版本 manifest。

不得扩大本阶段范围：不实现自定义岗位编辑器、自动招聘决策、多人云协作、自动更新器、安装向导或新的供应商私有协议。不要连接真实付费模型、下载飞书简历附件、修改飞书数据、推送远端、创建提交或生成正式发布产物，除非当前任务另有明确授权和费用/数据范围。

飞书三个岗位表只能作为待去重、脱敏、双人独立定标的候选来源。筛选状态是弱标签，面试和录用结果只用于人工仲裁，不能作为被评估模型的输入；未筛选、待定、取消和空状态不得直接当负例。任一岗位少于 50 份定标样本，或可靠正例少于 30 份时，只报告样本量和观察值，不显示“岗位已校准”。

每完成一个阶段，运行最小相关测试；全部实现后运行完整 unittest、源码离线 smoke、Tk UI 测试和必要的静态检查。随后检查最终 diff，确认没有真实简历、.env、数据库、日志、授权缓存或明文密钥进入提交范围。生成 UI 截图进行视觉检查，但不要把单张合成截图描述为 DPI、读屏或独立设备验收。

如果获得单独的构建授权，再分别构建 Windows 目录版和 onefile 版。每份产物生成独立、不可覆盖的 manifest，包含版本、commit、lock hash、平台/架构、Python/PyInstaller、OCR 模型 hash、签名状态、产物 SHA256 和 smoke 证据。目录 ZIP 是默认推荐包，onefile 是次选便携包。

只有在两台独立、无 Python/uv 的 Windows 11 x64 设备完成中文用户名、空格路径、离线 OCR、批量流程、数据迁移/恢复、凭据、125%/150% DPI 和键盘验收，并且经授权完成 MiniMax 与至少一个 OpenAI-compatible 真实小样后，才更新 desktop-user-guide.md 和 desktop-validation.md 并声明 0.3.0-preview Windows 内部预览版已交付。Mac 继续明确标记未生成、未真机验收、未签名公证。

最终汇报必须分别列出：已实现并验证、已实现但未完成外部验收、未实现/不在范围、测试和构建证据、仍需用户或外部环境提供的条件。只报告实际运行过且结果已检查的验证。
```
