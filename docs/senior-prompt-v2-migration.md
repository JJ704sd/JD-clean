# 资深全栈 Prompt v2 迁移

## 变更目标

日志基线显示 prompt v1 的 14 份资深全栈简历中仅 1 份通过完整输出契约；其余已完成响应主要违反二审枚举、追问数量、重复原因码和文本长度约束。Prompt v2 将证据判断与流程记录组装分离。

## 兼容矩阵

| 任务版本 | 模型写入 | Python 读取 | 审计处置 |
| --- | --- | --- | --- |
| `resume-screening-prompt-2026-09-01-v1` | 完整筛选记录 | 原完整记录校验路径 | 只读保留，不原地修改 |
| `resume-screening-prompt-2026-09-01-v2` | `evidence`、`uncertainties`、`interview_probes` | Python 组装完整 Schema 1.2 记录 | 新写入默认 |

Schema 1.2、资深全栈 rubric v6、评分版本和导出结构均保持不变。`prompt_version` 已包含在 SQLite `task_key` 中，因此同一来源在 v1 与 v2 下是不同的可审计任务，不覆盖旧任务记录。

## 权威边界

- MiniMax：原文证据、证据强度、置信度、决策相关疑点、上下文化追问。
- Python：身份与版本、建议状态、Go 硬门槛、物流与重构信号、原因码去重、追问数量、摘要、人工审核字段、分数和档位。
- v1 的已完成无效响应保持人工处理；不得把其错误记录原地改成成功。
- v2 重筛必须进入独立批次，并继续遵守每个 v2 任务最多一个完成模型响应。

## 恢复与观察

v2 上线前使用假模型覆盖推进、二审和暂不推进三个分支，并通过角色自有校验器。若真实小批次仍出现 `INVALID_MODEL_OUTPUT`，停止批次，保留 v1/v2 数据库和输出目录，禁止自动重试已完成响应；根据新错误发布后续 prompt 版本。
