# 资深全栈 v7 契约迁移

## 目标

在保留 Go 项目证据硬门槛的前提下，将证据强度、能力档位和人工复核状态拆开：模型只抽取事实，Python 生成 `E0`–`E3`；证据档位只按分数区间生成，`review_status` 单独表达推进或二审流程。

## 版本矩阵

| 组成 | 历史版本 | 新写入版本 | 兼容策略 |
|---|---|---|---|
| Schema | `1.1` / `1.2` | `1.2` | 继续读取已支持的历史记录 |
| 高级全栈 rubric | v2–v6 | v7 | v6 保留 Go 硬门槛语义；新任务按 v7 重筛 |
| Parser | `resume-cleaner-2026-09-01-v1` | `resume-cleaner-2026-09-01-v2` | v2 剥离平台长令牌并触发 OCR；旧待处理任务不混用新解析器 |
| Prompt | v1–v3 | `resume-screening-prompt-2026-09-01-v4` | v4 的高级全栈负载使用五字段事实清单，不接收模型自报 `strength` |
| Scoring | `evidence-score-2026-09-01-v1` | `evidence-score-2026-09-01-v2` | 历史 scorecard 不改写；v2 新增 `review_status`，档位只按分数生成 |

## 新写入规则

1. 文件名存在明确岗位前缀且与 `--role` 冲突时拒绝入队；无明确前缀的单份简历仍允许人工指定岗位。
2. PDF 文本层只包含平台长令牌时先剥离令牌并执行 OCR；仍无可靠正文时进入 `U01_PARSE_QUALITY`，不调用模型、不生成 0 分记录。
3. 高级全栈模型证据项提供 `project_context`、`personal_action`、`method_or_tradeoff`、`result_scope`、`verifiable_impact`。前两项齐全才可为 E2，五项全部齐全才可为 E3。
4. `U01/U09/U10/U11` 不再直接接受模型自报。解析器负责 U01；Python 根据明确求职意向生成 U09、根据严格指令模式生成 U11；冻结版本下不由模型生成 U10。
5. 明确缺少合格 Go 项目证据时，其他不会改变该门槛结论的疑点被过滤；安全相关 U11 仍保留独立复核。
6. 证据档位区间为 A≥85、B≥70、C≥55、D≥40、E<40。`model_recommendation` 与 `review_status` 保留 Go 门槛和人工复核流程，不能被高分覆盖。

## 迁移与恢复

- 已完成的 v2–v6 记录只读保留，不原地补字段、改档位或重算。
- 旧解析/提示/评分版本的待处理任务进入 `STALE_CONTRACT_VERSION` 人工队列；从原始文件重新 enqueue 会生成新的版本化任务键，不覆盖旧任务。
- v7 小批次必须先核对岗位路由、解析成功率、E3清单和二审原因，再扩大批量。
- 若 v7 写入失败，保留失败记录和原始任务；修复后以前向新版本重筛恢复，不回写历史结果。

## 收缩条件

只有在没有业务或审计消费者需要 v2–v6 记录、且代表性人工校准样本证明 v7 的岗位路由、解析、证据等级和复核状态均稳定后，才可另行移除旧版读取兼容。本次不执行收缩。
