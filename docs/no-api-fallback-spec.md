# 无付费 AI API 保底方案

日期：2026-09-07。状态：保底模式已实现并通过 Windows 独立包离线验收；Mac 未实测。详见 [验收记录](desktop-validation.md)。

## 1. 结论与适用范围

没有付费 AI API 时，应用仍须能独立完成简历导入、本地文本提取/OCR、原文定位、岗位材料整理、人工审阅和结果导出。保底模式不依赖云端模型，也不依赖本地大语言模型，适用于主规格约定的 Windows x64、MacBook Air Apple Silicon 与 Intel。

默认方案为“本地整理 + 人工审阅”。可选本地模型属于后续增强，不作为首版交付前提。该方案免模型 API 费用，但不承诺自动完成现有 AI 证据判断，也不消除人工审核时间。

本文件补充 one-click-app-spec.md。对于首次配置必须填写 API、无密钥阻断处理等冲突，以本文件的桌面流程为准；既有 CLI worker 的无密钥保护保持不变。

## 2. 三种使用条件

| 条件 | 可完成工作 | 不能承诺的结果 |
| --- | --- | --- |
| 无 API、无本地大模型，首版保底 | 提取/OCR、岗位分组、检索线索、人工意见、导出 | 自动语义取证、AI 评分或推进建议 |
| 用户以后配置付费 API | 沿用主规格的模型取证、结构校验与 Python 评分 | 无人工复核的最终招聘决定 |
| 用户以后配置本地大模型，增强项 | 经兼容和质量验证后提供辅助取证 | 任意电脑流畅运行、与现有模型等效的质量 |

免费云服务额度、网页聊天账号或浏览器自动化不作为保底依赖。不要求使用者寻找免费额度，也不通过模拟网页登录绕过 API 接口。

## 3. 首次启动与日常操作

首次启动提供“无需 API，开始本地整理”和“配置模型 API”两个入口。选择前者不弹出必填密钥错误，不发起模型连接测试。

1. 导入文件或目录，支持现有 PDF、DOCX、TXT、MD。
2. 选择现有三个岗位之一，或沿用文件名前缀自动分流；未知岗位留待指定。
3. 点击“开始整理”，本地提取文本，必要时 OCR，记录来源与解析质量。
4. 展示“待人工审阅”列表，左侧原文/提取文本，右侧岗位检查项及人工备注。
5. 审阅者记录判断、证据和需追问事项，保存后标记为“人工审阅完成”。
6. 导出审阅表和可追溯材料；以后配置模型时可显式选择记录进行 AI 分析。

本地整理完成只表示材料可供审阅，不显示“AI 初筛成功”。没有配置模型不阻止进入主界面、查看历史或导出。

## 4. 保底功能定义

### 4.1 提取与质量

复用 cleaning.py 的文档读取、OCR、来源哈希和质量检测。OCR 模型与依赖须随独立包提供；首次启动与断网运行都不得临时下载模型。

每份材料显示文件名、岗位、页码或段落位置、解析状态。扫描质量差、空白和文件损坏进入“解析失败/待核对”，不得以缺失文本判定候选人不符合。

### 4.2 线索与人工审阅

岗位检查项来源于现有岗位资料及版本，不另外维护一套评分规则。首版提供原文搜索、关键词位置和上下文，标记为“检索线索，待人工确认”。

例如简历出现 WMS，只能定位该词及所属项目，不能直接认定具有物流经验或高含金量项目；出现院校名称不能自动认定第一学历。没有命中也不等于不具备。

人工审阅记录包含：审阅者填写的名称、时间、岗位及规则版本、逐项结论、证据引用、备注和需追问问题。审阅者名称为本机自填信息，不是经过登录认证的身份。

逐项结论允许“有证据支持”“不符合”“信息不足”“未审阅”。选择支持或不符合时要求附原文引用或明确人工备注。证据不足允许保留为信息不足，不能强制填满。

首版保底模式不计算 A–E、总分和自动推进建议。人工填写的整体意见明确标记为人工意见，不伪装成现有模型输出。若以后要求人工结构化取证后复用评分，须另补字段映射与合同验证规格。

### 4.3 导出

保底导出使用独立的 manual-review.csv 和每份材料的 review.md；包括候选人本地标识、来源、岗位、解析状态、审阅状态、人工意见与记录位置。

未审阅记录保留“待人工审阅”，AI 模型、AI 评分等不存在的字段留空，不填零分。CSV 对可能触发电子表格公式的外部文本做安全转义。

保留本地原文与脱敏文本的区分；如以后用于模型，只取现有脱敏处理后的输入，不直接发送人工备注或原始简历。

## 5. 状态与兼容性

保底流程采用独立状态：待整理 → 整理中 → 待人工审阅 → 人工审阅完成；解析失败为可修复分支。

使用独立的本地整理/审阅记录存储，不把这些状态写入既有 AI 任务状态枚举，不生成虚假的 screening.json。具体表结构在实现时版本化，并记录迁移与回滚方式。

- 去重基于来源内容与岗位/解析版本；人工修订保留历史或修订编号。
- 进入 AI 模式时显式创建关联的 AI 任务；不覆盖人工记录，不自动补跑历史材料。
- AI 密钥失效、额度不足或网络失败时暂停相应队列，提供“继续本地整理”入口。
- 已发送且远端完成状态不明的请求继续保留原始不明状态，不能因为切换模式而重置并自动重试。
- 本地整理与 AI worker 共享来源时，需要协调清洗产物写入，禁止两个执行器同时覆盖同一输出文件。

## 6. 可选本地模型增强

后续可增加“本地模型”提供方，但不随首版强制安装大型模型。具体运行器、模型、许可证、内存与系统门槛必须在选型时核查一手资料，并在对应 Windows/Mac 设备实测；本规格不预设未经验证的硬件数字。

接入条件包括：中文简历和现有结构输出契约通过验证、长简历不静默截断、速度与内存可接受、模型文件来源与许可证可追溯。连接成功和 JSON 有效都不能单独证明判断质量合格。

如接入本机 HTTP 服务，使用独立提供方策略，仅允许明确的 loopback 地址，禁止跨主机重定向；不能为方便本地服务而取消云 API 的 HTTPS 校验。

本地模型缺失、运行失败或性能不足时，仍可进入本地人工模式。用户未选择启用时，不启动模型服务、不自动下载模型。

## 7. 飞书与离线边界

保底核心在断网时可用，飞书仍是需要联网和授权的可选集成。启用同步后可以发布已授权的整理材料；人工意见必须明确标注来源，不能写成 AI 已完成。

初始保底版本不自动新增飞书人工审阅字段，也不更改现有 AI 回写门禁。如需同步人工结论，应先确定字段映射，并沿用主规格的预检查和用户显式启用流程。

## 8. 验收标准

| 场景 | 通过要求 |
| --- | --- |
| 无密钥首次启动 | 可跳过配置并完成导入、整理、人工审阅与导出 |
| 断网且无缓存的干净安装 | OCR 资源齐全，支持的文件可处理，不请求云端或下载模型 |
| Windows/Mac 两种架构 | 分别实际完成完整保底流程，未测平台不能标记通过 |
| 未知岗位/岗位冲突 | 要求明确指定或跳过，不强制混入已有岗位 |
| 扫描件与损坏文件 | 有质量提示，失败材料不生成零分或否定判断 |
| 关键词命中与未命中 | 仅展示检索线索，不生成 AI 评分或自动推荐 |
| 人工审阅 | 信息不足可保存，已判定项有证据或备注，来源明确 |
| 关闭重启/重复导入 | 记录与审阅意见保留，不重复覆盖 |
| 模式切换 | 人工记录与 AI 记录关联但隔离，不自动发送历史简历 |
| 导出 | 待审阅状态明确，不伪造模型信息，公式文本不会执行 |
| API 请求结果不明 | 切换保底后仍不自动重发付费请求 |
| 网络隔离检查 | 保底核心完整流程无模型网络调用；飞书未启用时无飞书请求 |

## 9. 实施顺序与交付物

优先实现保底模式，使桌面应用在无密钥条件下即可验收；再接入主规格的付费 API。顺序为：资源独立打包 → 本地整理服务 → 首启模式选择 → 原文与人工审阅界面 → 独立存储及导出 → 三平台离线验收 → AI 模式切换回归。

目标交付物包括与主规格共用的三个平台包、无 API 使用说明、合成测试材料、离线与状态兼容验收报告。当前已有 Windows 免安装预览包和构建源码；Mac 平台包仍待对应构建环境。
