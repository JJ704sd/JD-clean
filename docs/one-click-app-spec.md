# 简历初筛桌面应用构建规格

日期：2026-09-07。状态：已实施 Windows 桌面预览版并打包；Mac 构建、签名和完整跨平台验收待完成。实施情况与差异见 [验收记录](desktop-validation.md)。

补充规格：[无付费 AI API 保底方案](no-api-fallback-spec.md)。桌面首启允许跳过模型配置，进入本地整理与人工审阅；该补充在无 API 流程上优先于本文件的必填配置描述，其他付费模型及平台要求保持适用。

## 1. 目标与确认范围

将现有 Python 脚本交付为中文桌面工具。使用者安装后双击启动，不需要 Python、uv、终端或 Codex。首次配置自己的模型 API，之后可导入简历、选择岗位、筛选、查看结果和导出。

用户明确要求 Windows 与 MacBook Air、自费模型 API 可更换。按最后一轮“是的”对推荐方案的确认，首版采用以下范围：

- Windows x64；macOS Apple Silicon arm64 与 Intel x64，分别构建。
- 本地筛选独立可用；飞书为可选集成，未配置时不阻断本地功能。
- 固定 AI 产品经理、资深全栈工程师、全栈开发实习生三个现有岗位及规则。
- 支持 MiniMax 原有协议和 OpenAI 兼容 Chat Completions 协议；不承诺任意厂商原生协议可用。
- 每台电脑独立存储配置和任务。无团队账号、共享服务器和多人协同。

“一键使用”指安装和首次配置完成后的双击启动，不代表免密钥、免联网或免飞书授权。模型服务费用由使用者自行承担。

## 2. 当前证据与缺口

依据 README.md、pyproject.toml、resume_screening/cli.py、minimax.py、prompts.py、feishu_monitor.py 的静态检查：

| 已有基础 | 构建缺口 |
| --- | --- |
| PDF/DOCX/TXT/MD 清洗、OCR、脱敏 | 验证 OCR 模型文件和原生库可随包分发并离线加载 |
| SQLite 队列、租约、恢复、导出和健康状态 | 将状态转成可操作界面，管理进程退出和重复启动 |
| 三个岗位的提示词、校验与确定性评分 | 将 skills 资源纳入安装包，消除源码目录依赖 |
| MiniMax 客户端 | 增加协议适配、配置快照和通用密钥处理 |
| 飞书监控及文档发布脚本 | 可选安装引导、登录检测、字段映射与跨平台验证 |
| Python 3.12 与 uv 锁定依赖 | 独立运行时、安装包、签名与各架构发布流程 |

当前尚无图形界面、安装包或干净机器验收证据。现有工作区 .env、简历、输出、数据库与飞书会话均不得作为发行资源。

## 3. 用户流程

### 3.1 首次打开

1. 创建当前用户专属数据目录，检查写入权限和资源完整性。
2. 选择 MiniMax 或 OpenAI 兼容接口，填写 HTTPS Base URL、模型名、API Key。
3. 点击“测试连接”：只发送合成短文本，明确说明可能产生少量 API 费用，展示认证、模型可用性和输出协议检查结果。
4. 保存配置，进入任务页。飞书设置可跳过。

连接测试通过不等于该模型具备合格的简历判断质量。首次更换模型建议先筛一份并人工核对；不得自动回退到另一收费服务。

### 3.2 筛选与结果

1. 选择文件或目录，展示可处理文件及忽略原因。
2. 选择固定岗位或按已有文件名前缀自动分流；岗位冲突不得强制混入，无标签文件需要明确指定岗位。
3. 展示数量、岗位和所用模型，用户点击“开始筛选”后才调用模型。
4. 展示待处理、处理中、成功、失败及需人工复核；提供停止接收新任务、查看错误、显式重试入口。
5. 结果页显示证据、结论、评分、规则版本和复核信息；支持打开原文、打开输出目录、导出现有结果格式。
6. 可选开启目录监听；沿用文件稳定性检查和去重机制。默认不注册开机启动。

默认关闭窗口时提示“当前任务结束后退出”或“返回应用”；无任务时直接退出。请求已经发出后不得将本地停止解释为远端未计费。

### 3.3 页面范围

- 任务页：导入、岗位选择、开始/停止监听、队列状态和错误处理。
- 结果页：结果列表、证据与结论、人工复核信息、导出。
- 设置页：模型配置及测试、数据位置、可选飞书配置。
- 诊断页：版本、资源检查、worker 状态和脱敏诊断导出。

## 4. 模型接口与兼容约束

沿用 analyze(system_prompt, resume_text, model, idempotency_key) 的调用意图和 ModelResponse 的 content、response_id、usage 语义，业务流水线不直接拼装供应商请求。

- MiniMax 适配器保留原有协议和业务错误解析。
- OpenAI 兼容适配器使用非流式 Chat Completions；Base URL 与路径拼接规则必须唯一，避免重复 /v1 或 /chat/completions。
- 不无条件复制 MiniMax 的 name、temperature、top_p、max_completion_tokens 参数；适配器只发送所声明支持的参数。
- 返回内容仍须经过现有结构和证据校验，分数由 Python 计算；格式错误不生成成功结果，也不自动追加付费“修复请求”。
- 认证失败暂停消费；限流使用有界退避；超时和远端是否完成不明时进入需确认状态，禁止盲目重发。
- 不把请求 ID 等同于供应商计费幂等保证。
- 每个任务固化协议、端点标识、模型和规则版本；密钥仅引用本机凭据条目。任务进行中切换设置只影响后续任务。
- 更换模型不自动重跑已有结果；重跑创建有来源关联的新运行记录，保留历史输出，避免现有去重键误复用其他模型结果。
- 保留现有 CLI 的环境变量用法；新增桌面配置不得改变旧命令的默认行为。

API Key 存入 Windows 当前用户受保护凭据或 macOS Keychain；普通配置只保存凭据引用。不得写入日志、导出、命令参数或安装包。配置 HTTPS 地址时校验格式，跨域重定向不得携带 Authorization。模型只接收沿用现有逻辑脱敏后的简历正文。

## 5. 本地运行与数据

桌面展示层调用应用服务层，应用服务层复用现有清洗、队列、评分、校验与导出模块。耗时解析和网络请求在后台执行，不阻塞界面；界面关闭、工作进程退出和异常恢复采用显式生命周期管理。

资源路径与可写路径分离：

- 安装资源只读：岗位 skills、版本信息、OCR 模型及运行库。
- Windows 数据默认位于当前用户 LOCALAPPDATA 下的应用目录。
- macOS 数据默认位于当前用户 Library/Application Support 下的应用目录。
- 不依赖当前工作目录，不写入安装目录，支持中文及带空格路径。
- 默认不接管开发目录已有数据库；提供显式导入时先备份，校验版本，失败回滚。
- 一个数据目录只允许一个活跃消费者；重复启动聚焦已有窗口或明确提示。
- 数据库结构变化必须有版本迁移与备份；升级不得静默清空历史。
- 卸载默认保留用户数据；清除数据属于独立显式操作。

UI 框架与打包器尚未作为用户确认项。本规格要求先通过第 8 节的三平台最小打包验证，再记录选型及依赖许可，避免在未验证原生 OCR 依赖前锁定完整实现。

## 6. 飞书可选模块

本地使用不要求安装或登录 lark-cli。启用飞书后，提供依赖检测、登录状态、Base/表/文档文件夹配置及字段映射；不复制开发者的 token、授权缓存或固定表 ID。

保留现有 dry-run、表结构门禁、唯一匹配、文档回读和幂等逻辑。在界面中先展示预检查结果，用户点击启用同步后才执行相应写入。依赖缺失、授权过期和字段变化应显示可执行的修复提示，并暂停对应同步。

首版可通过引导安装外部 CLI 满足可选功能；不得将“本地免环境”宣传成“飞书免授权”。完成本地版本不代表飞书模块通过验收。平台 CLI 支持和分发许可须在实现时核实。

## 7. 发行与验收

发行目标为 Windows x64 安装包、macOS arm64 与 x64 应用分发包；各包包含运行时、依赖与必需资源。不得要求用户手动下载 OCR 模型。最低 OS 版本在原生依赖构建验证后写入发布说明，未经验证不得承诺兼容旧系统。

在各自系统与架构构建或使用明确支持该目标的构建环境，分别完成干净机器验证。macOS 正式对外交付需要签名和公证流程；Windows 签名及信誉提示须据实际结果记录。无签名测试包必须标记测试用途，不能将关闭系统防护作为正常安装步骤。

| 验收场景 | 通过标准 |
| --- | --- |
| 无 Python/uv 的干净设备 | 三个目标均能安装、双击启动、卸载，无命令行操作 |
| 中文用户名和空格路径 | 导入、OCR、数据库和导出正常 |
| 原生 PDF、扫描 PDF、DOCX、TXT、MD | 清洗有内容且可追溯；空白或损坏文件报告解析失败 |
| 三个岗位 | 沿用现有合同校验，岗位冲突和未知文件正确处理 |
| 模型协议 | 两类适配器有合成数据契约测试；真实调用另行用有效凭据验证 |
| 密钥无效、限流、断网、超时、错误 JSON | 状态准确，不假报成功，不盲目重复付费 |
| 进程崩溃、重复启动、恢复运行 | 租约与去重有效；不明请求保留待确认状态 |
| 更换模型 | 新任务使用新配置，旧结果可追溯且不被覆盖 |
| 密钥与发行内容 | 发行包无 .env、私人简历、数据库、日志和授权缓存 |
| 升级安装 | 配置与历史保留，迁移失败可恢复备份 |
| 飞书未启用 | 全部本地功能可用 |
| 飞书启用 | 各目标平台登录检测、预检查、导入回读、幂等和错误恢复通过 |

## 8. 构建顺序与完成门槛

1. 基线：检查并运行现有相关测试，记录既有失败；不连接真实飞书，不消耗模型费用。
2. 可行性原型：三个目标分别运行带 OCR、skills 读取和 SQLite 的最小独立包。验证锁定依赖是否有对应架构产物、是否需要兼容迁移；确定 UI 与打包工具，记录最低系统和资源体积。
3. 核心适配：模型接口、凭据与配置、资源路径、任务配置快照及必要数据库迁移；对现有 CLI 做兼容回归。
4. 桌面流程：完成首启、导入、任务、结果、导出和生命周期管理，以合成简历验收。
5. 可选飞书：配置向导及现有门禁封装，隔离本地流程与同步失败。
6. 发布：三个目标的安装包、版本及校验值、许可证清单、安装说明、验收报告，完成签名与真实设备检查后再声明可正式交付。

当前环境为 Windows，不能替代 macOS 真机/构建机验证。签名身份、macOS 构建与测试环境、真实模型凭据和飞书测试空间属于发布前资源条件；在条件缺失时可继续本地实现，但相应验收必须标记“未验证”。

## 9. 不在首版范围与后续交接

首版不含自定义岗位/评分编辑器、其他厂商原生协议、公司代付网关、多用户服务、自动升级、开机自启和自动淘汰候选人。继续保持结果非最终招聘决策的现有边界。

本文件是构建的需求与验收依据，不是全部功能已实现声明。用户已明确授权构建，当前交付预览版；任何平台、功能或数据契约调整需更新对应条款及验收证据。
