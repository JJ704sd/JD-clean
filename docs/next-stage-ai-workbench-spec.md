## 3. 产品目标与边界

### 3.1 产品目标

ResumeDesk 是以本地整理和人工最终确认为底座、以 LLM 提升批量初筛效率的桌面工作台。下一版应使非技术招聘人员可以完成：

1. 批量导入 10–100 份简历并完成本地解析/OCR。
2. 明确选择一批材料后启动 AI 分析。
3. 根据可追溯证据、岗位档位、风险和建议对候选人排序。
4. 逐份人工确认、修订并保留完整历史。
5. 导出当前结论及可审计记录。
6. 在没有 API、断网、额度不足或模型不可用时继续人工工作流。

### 3.2 决策边界

- AI 可以生成证据、缺失/冲突、风险、建议、追问和排序依据。
- AI 不得自动推进、淘汰或形成最终招聘决定。
- AI 原始结果不可被人工就地覆盖；人工结论作为独立修订保存。
- “连接可用”和“岗位判断已校准”是两个独立状态。
- 解析失败、内容不足和模型结果不确定均不得转换为“不合格”。

### 3.3 本阶段不做

- 自定义岗位、JD 或评分规则编辑器。
- AI 自动推进或自动淘汰。
- 多用户账号、云端共享和实时协作。
- 自动更新器、安装向导或开机自启。
- 新增模型厂商私有协议；继续支持 MiniMax 和 OpenAI-compatible。
- 在没有对应真机证据时交付或宣传 macOS 包。

## 4. 不得破坏的现有不变量

1. PDF、扫描 PDF、DOCX、TXT、MD 的本地整理和人工审阅不依赖 API。
2. OCR 模型随发行包提供，最终用户运行时不下载模型。
3. 原始材料副本与发送给模型的脱敏文本严格分离。
4. 模型只接收脱敏后的材料正文；人工备注默认不发送给模型。
5. 模型请求必须由用户显式启动，并在批量开始前显示数量、模型、端点标识和可能计费。
6. API Key 只持续保存到 Windows 凭据库或 macOS Keychain；配置、备份、导出、日志和诊断不保存明文密钥。
7. Base URL 必须为 HTTPS，不得包含凭据、查询参数或片段；跨域重定向不得携带 Authorization。
8. 认证失败或限流暂停当前批次；格式错误、超时或远端状态不明不得自动补发付费请求。
9. 每次 AI 运行独立保存配置快照和规则版本，不覆盖人工记录或旧运行。
10. 桌面数据与原 CLI 数据隔离；升级不得静默清空用户材料、草稿、修订或 AI 历史。
11. 一个数据目录只允许一个活动实例；后台工作不得阻塞 UI。
12. 飞书未配置、未授权或同步失败不得影响本地核心流程。

## 5. 目标用户流程

### 5.1 首次启动

当数据目录为空时，材料页显示可关闭的三步引导：

1. 导入简历并选择固定岗位或按文件名前缀分流。
2. 完成本地解析；可以直接人工审阅，也可以选择一批材料进行 AI 分析。
3. 人工确认后导出。

引导必须列出支持格式、三个内置岗位、自动分流示例以及“无需 API 也可使用”。已有材料时不得反复阻断用户。

### 5.2 日常批量工作流

1. 用户导入文件或目录；目录递归默认关闭，可显式开启。
2. 导入预览显示总数、支持格式、岗位识别、重复、冲突、跳过和预计处理数。
3. 本地整理逐份显示 `n/N`，并生成可在界面打开的导入报告。
4. 用户通过筛选和多选创建 AI 批次。
5. 确认框显示材料数、岗位、模型、端点标识、可能重复计费数量和调用范围。
6. AI 批次显示排队、处理中、成功、失败、需人工核对和停止后的剩余数量。
7. 成功结果进入可排序的材料列表；人工打开结果、核对证据并保存结论。
8. 导出当前人工结论、AI 运行摘要和完整审计记录。

### 5.3 停止与退出

- “停止”只阻止后续材料发起新请求，不将已发送请求描述为远端已取消。
- 已完成结果必须保留。
- 关闭运行中的应用时，用户可选择等待当前项结束后退出或返回应用。
- 草稿必须在切换材料和退出前保存；保存失败时不得直接退出。

## 7. AI 输出合同

AI 适配器输出必须先转换为统一、版本化的结果，再进入 UI。概念合同如下；具体字段名可以在实现设计中调整，但语义和隔离边界不得删除：

```json
{
  "output_contract_version": "resumedesk-ai-result-v1",
  "document_id": "local-id",
  "role": "senior-fullstack-engineer",
  "input_redacted_sha256": "...",
  "provider": "openai-compatible",
  "endpoint_identity": "https-origin-and-path-without-secret",
  "model": "model-name",
  "rule_versions": {},
  "criteria": [
    {
      "code": "criterion-code",
      "assessment": "supported|not_supported|insufficient",
      "evidence": [{"location": "page-or-section", "quote": "short excerpt"}],
      "gaps": [],
      "risks": []
    }
  ],
  "computed_score": {"value": 0, "band": "E"},
  "model_recommendation": "advance|do_not_advance|manual_review",
  "summary": "...",
  "interview_questions": [],
  "uncertainty_reasons": [],
  "created_at": "ISO-8601"
}
```

约束：

- `computed_score` 和档位继续由 Python 根据已验证事实计算，不接受模型自报分数作为最终值。
- `evidence.quote` 必须能在该次发送给模型的脱敏文本中定位；无法定位的证据不得计分。
- 不确定性使用原因和证据覆盖状态表达，不展示未经校准的伪精确概率。
- 原始模型响应、规范化结果和校验错误分别保存，且均不得包含 API Key。
- `model_recommendation` 只影响排序和提示，不改变人工状态。

## 8. 数据与迁移要求

### 8.1 概念实体

- `Document`：原始材料副本、脱敏正文、岗位、解析版本和本地状态。
- `ImportBatch`：一次导入的预览、处理统计和逐文件报告。
- `AiBatch`：用户确认的一批材料、模型配置引用、计费确认和批次进度。
- `AiRun`：单份不可变模型运行、规范化输出和错误状态。
- `ManualRevision`：人工结论、证据备注、操作者自填名称和时间。
- `TrashEntry`：删除时间、计划永久清除时间和恢复所需关联。

### 8.2 schema v1 到下一版本

当前桌面数据库为 schema v1。实现必须提供显式迁移，不得通过删除数据库重新初始化。迁移至少支持：

- AI 结果合同版本和输入脱敏内容 hash。
- AI 批次及其与逐份运行的关系。
- AI 不可变输出与人工确认/修订的关联。
- 材料软删除时间、计划清除时间和恢复状态。
- 导入批次与逐文件结果。

迁移前自动创建数据备份；迁移失败时恢复原状态并给出可操作错误。较新且不支持的 schema 继续拒绝打开，不得尝试降级写入。

### 8.3 删除语义

- 普通删除进入回收区，默认 7 天后永久清除。
- 恢复必须恢复材料及其草稿、人工修订和 AI 历史关联。
- 立即永久清除和清空全部数据必须二次确认，完成后报告清除范围。
- 清除数据库记录时同步清除应用管理的原始副本、提取文本和 AI 输出目录。
- 操作系统凭据使用独立入口清除，不能因删除一份简历而删除共享端点凭据。
- 删除仅作用于本机；不得暗示会删除飞书或模型供应商侧数据。

## 9. 模型校准与飞书材料

### 9.1 候选数据来源

截至 2026-09-09，对用户授权参考的飞书多维表进行了只读聚合核查，未在本文记录姓名、联系方式或简历正文：

| 岗位 | 简历收集表记录/有附件 | 面试推进表记录/有附件 | 当前标签限制 |
| --- | --- | --- | --- |
| AI 产品经理 | 105 / 104 | 28 / 26 | 收集表中“可约面+已约面”仅约 13；推进表没有最终状态。 |
| 资深全栈工程师 | 103 / 101 | 15 / 14 | 收集表中“已约面”约 8；推进表最终状态为 8 条已淘汰、7 条空。 |
| 全栈开发实习生 | 56 / 55 | 5 / 4 | 收集表中“可约面+已约面”约 3；21 条尚未筛选。 |

上述数量是动态数据的当时快照。收集表与推进表可能包含同一候选人的不同附件副本，不能直接相加，也不能据此宣称已形成每岗 50 份均衡金标准。

### 9.2 标签原则

- 校准目标是“仅根据简历是否值得进入人工/面试复核”，不是预测最终录用。
- 收集表的筛选状态只作为弱标签。
- 面试评价和最终状态可以帮助人工仲裁，但不得作为待评估模型的输入。
- “未筛选”“待定”“已取消”和空状态不得直接当作负例。
- 同一候选人或相同内容不得跨开发集和保留测试集。

### 9.3 建集流程

1. 经明确的数据使用授权后，在受控本地目录取得所需附件。
2. 计算附件内容 hash，合并重复材料，保留来源记录 ID 而不在校准清单暴露姓名。
3. 使用当前岗位规则，由两名审阅者仅查看简历独立标注 `advance`、`do_not_advance` 或 `manual_review`。
4. 分歧由第三次仲裁或共同复核解决，并记录原因。
5. 每岗第一阶段至少形成 50 份定标样本；在可靠正例少于 30 份时，不宣称已经可靠验证 90% 正例召回率。
6. 冻结不参与提示词调整的保留测试集；模型、提示词或规则变化后重复同一评估。

任何附件下载、脱敏、真实模型调用或付费评估均属于单独执行步骤；本文创建本身不代表这些步骤已经完成。

### 9.4 质量门槛

只有同时满足以下条件，某个“岗位+规则版本+模型+端点”组合才能在 UI 中标记为“岗位已校准”：

- 人工定标为 `advance` 的样本召回率不低于 90%。
- AI 引用证据在脱敏输入中的可定位率不低于 95%。
- 结构输出通过合同校验的比例不低于 98%。
- 自动推进和自动淘汰次数为 0。
- 测试样本、模型、端点、提示词、规则和结果版本均可追溯。

样本不足时可以显示实际观察值和样本量，但不得显示“已校准”。

## 10. UI 信息架构

继续采用单窗口工作台和四个顶层页签：

1. **材料与审阅**：导入、批量选择、AI 状态、排序、原文、AI 建议和人工确认。
2. **模型与设置**：简化模型配置、连接/校准状态、数据位置、备份、恢复、回收区和凭据管理。
3. **AI 历史**：批次和逐份运行，只读展示配置快照、状态、错误及导出。
4. **飞书（可选）**：保持本地功能隔离，不默认启用写回。

材料表至少显示材料名、岗位、本地状态、AI 状态、AI 档位/建议、主要风险、人工状态和最后更新时间。多选时详情区只展示当前焦点材料，同时明确显示已选总数。

右侧详情区建议分为“AI 建议”和“人工审阅”两个内部页签，避免将 AI 输出伪装成人工结论。AI 页为只读；人工页继续支持草稿自动保存。

## 11. 隐私与安全

- 不得宣传本地材料或备份已做静态加密；当前保证是本地保存，不等于加密保存。
- 备份包含简历和人工审阅内容，应在选择目标目录前明确提示其敏感性。
- API Key 不得进入普通配置、数据库、日志、诊断、备份、导出、模型请求正文或命令参数。
- 错误信息和导入报告不得回显 Key、Authorization 或完整供应商响应。
- AI 证据摘录在 UI 和导出中按业务需要最小化；诊断继续不包含简历正文。
- 飞书校准材料不得在未授权情况下批量下载或发送给第三方模型。

## 12. 构建、升级与发布

### 12.1 Windows 分发

- 目录 ZIP 是默认推荐产物；onefile EXE 是次选便携产物，并明确首次启动较慢。
- 下一内部预览版先承诺 Windows 11 x64、普通用户权限。
- 继续标记签名状态；未签名包不得包装成低摩擦正式公开发布。
- 0.3 预览阶段采用手工替换程序目录；用户数据继续位于独立数据目录。

### 12.2 独立验收

发布前至少在两台没有 Python/uv 的独立 Windows 11 x64 设备验证：

- 目录版和 onefile 版启动、退出和重复启动。
- 中文用户名、中文/空格路径及普通用户权限。
- PDF、扫描 PDF、DOCX、TXT、MD 本地整理；运行时阻断网络确认 OCR 不下载。
- 10–100 份批量导入、停止、失败隔离和报告。
- 草稿、修订历史、回收、恢复、永久清除、备份与迁移回滚。
- Windows 凭据写入、读取和清除。
- 125%/150% DPI、1366×768 和键盘核心流程。
- 真实 MiniMax 及至少一个 OpenAI-compatible 端点的小样、限额调用。

真实 API 验收只使用获准脱敏样本，预先确定费用上限；记录模型、端点标识、规则版本、样本集版本和差异，不记录密钥。

### 12.3 构建证据

每份产物的 release manifest 至少包含：

- 应用版本及 Git commit。
- 目标 OS、架构和最低系统。
- Python、PyInstaller 和锁文件 hash。
- 直接依赖和 OCR 模型 hash。
- onedir/onefile、签名状态和产物 SHA256。
- 关联的测试、离线 smoke、凭据 smoke 和独立设备验收记录。

目录版和 onefile 版的 manifest 不得由后一次构建覆盖前一次证据。

### 12.4 macOS

源码继续保留 macOS 构建入口，但 0.3 Windows 内部预览不得因此宣称 Mac 已支持。macOS 状态仍按 2.3 节单独推进。

## 13. 实施顺序

1. 建立版本单一来源、持久化 schema 迁移和独立 release manifest。
2. 实现删除/回收区、凭据清除和可见的人工修订历史。
3. 实现首次引导、导入预览/报告、统一忙碌态和批量选择反馈。
4. 实现版本化 AI 输出合同、批次模型和主列表 AI 排序。
5. 简化模型设置并区分连接、真实调用和校准状态。
6. 补键盘、DPI、小屏和错误状态验证。
7. 使用合成材料完成自动测试和本机 smoke。
8. 在单独授权下建立飞书校准集并执行限额真实模型评估。
9. 在两台独立 Windows 11 x64 设备完成发布验收。
10. 验收通过后才构建并命名 0.3.0-preview 产物、更新用户指南和验收记录。

## 14. 完成定义

以下条件同时满足才可称为“ResumeDesk 0.3.0-preview Windows 内部预览版已交付”：

- P0、P1 要求全部实现并通过相应测试。
- schema 迁移、备份和失败回滚通过。
- 当前源码测试和两类 Windows 包 smoke 通过。
- 两台独立 Windows 11 x64 设备验收通过。
- 真实 MiniMax 与一个 OpenAI-compatible 小样验证完成。
- 每份产物具有不可覆盖的 manifest、SHA256 和已知限制。
- 发行包不含 `.env`、真实简历、数据库、日志、授权缓存或明文密钥。
- 文档明确目录 ZIP、onefile、源码和未交付 Mac 包的不同状态。

飞书校准集或某个模型组合若未达到第 9 节门槛，应单独标记“样本不足”或“未校准”，不阻止无 API 人工流程使用，但不得宣传对应模型质量已经验收。
