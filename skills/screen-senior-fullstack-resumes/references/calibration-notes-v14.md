# 全栈工程师 v14 校准记录

- 版本：`senior-fullstack-2026-09-14-v14`
- 生效日期：2026-09-14
- 基线：v13 的证据化初筛、Python 确定性评分、人工最终确认流程
- 历史版本：v13 及更早版本只读保留；按 v14 重筛时创建新版本任务，不原地改写历史记录

## 本次规则变更

将“第一学历本科及以上”新增为独立硬门槛。第一学历依据简历教育经历中足以还原的时间顺序，识别中等职业教育及以上最早已完成或已取得的学历层次（如中专、职高、技校、大专、本科及以上）；在读、肄业、未取得毕业资格不算已取得学历。只有在读本科而无首个已取得学历记录时为 `unclear`，进入二审；不得仅凭“本科在读”通过第一学历门槛。不以最高学历代替，也不以学校品牌、校名或全日制标签推断学历层次或顺序。

`SEN-ADM-01.first_education` 是模型提供给 Python 的结构化证据，字段为 `level`、`excerpt`、`location`、`confidence`。`level` 只允许 `bachelor_or_above`、`below_bachelor`、`unclear`。清晰层级必须有可定位的简历原文和位置；未知层级必须返回 `unclear`。

## 状态校准

| 简历证据 | 第一学历状态 | 机器建议 | 说明 |
|---|---|---|---|
| 教育经历按时间顺序明确显示首段学历为本科或更高，摘录和位置完整，置信度高 | `met` | 继续其他维度判断 | 后续学历不是必要条件 |
| 教育经历明确显示首段为大专、中专等低于本科的学历，摘录和位置完整，置信度高 | `not_met` | `do_not_advance_pending_human` | 后续取得本科或更高学历不覆盖该首段学历；仍须人工一审 |
| 只写硕士、本科等最高学历，没有足够教育时间顺序或首段学历信息 | `unclear` | `second_review` | 不能从最高学历推断第一学历 |
| 学历记录缺页、解析不完整、时间顺序不清或层级/时间冲突 | `unclear` | `second_review` | 有冲突时使用 `U03_CONFLICTING_FACTS`；其他边界不明使用 `U06_BOUNDARY_CASE` |
| 出现学校名称、校名声誉或“全日制/非全日制”字样，但未明确学历层级/顺序 | `unclear` | `second_review` | 学校与学习形式不能代理学历层级或第一学历 |
| 明确首段学历低于本科，但摘录、位置或解析置信度不足 | `unclear` 或低置信待核验 | `second_review` | 不以不可靠文本自动触发硬门槛 |

## 审核边界

- `do_not_advance_pending_human` 是待人工一审的机器建议，不代表删除简历、拒绝候选人或 ATS 最终决定。
- 第一学历不明确时二审；复核人员应回到原始简历核对教育原文、页码/位置和时间顺序。
- `not_evidenced` 只表示简历未提供充分证据，不等于候选人不具备该学历或其他能力。
- 原文证据可定位但项目经历/能力证据薄弱时，仍按对应 Rubric 判断；不得把学历硬门槛外推为其他维度的能力结论。
- 薪资、地点、到岗时间、沟通取消和求职意愿仍作为流程/商业或意向原因单列，不改变能力评分。

## 回归案例

1. 首段记录明确为“大专”，后续教育经历明确取得成人本科：第一学历为 `below_bachelor`；高置信时建议 `do_not_advance_pending_human`。
2. 首段记录明确为“中专”，后续记录只有最高学历“硕士”：第一学历仍为 `below_bachelor`；高置信时建议 `do_not_advance_pending_human`。
3. 只出现“硕士研究生”且没有首段教育信息：第一学历为 `unclear`，建议 `second_review`。
4. 仅凭学校名称或“全日制”推断学历等级：禁止分类；返回 `unclear` 并二审。
5. 首段教育记录 OCR 不清、日期顺序冲突：返回 `unclear` 并二审；不可自动拒绝或忽略冲突。
