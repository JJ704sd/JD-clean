# 招聘者结论卡格式

默认只展示本结论卡。详细 criterion 矩阵和 JSON 是按需审计层，不应挤占招聘者的首屏结论。

已有合法 JSON 记录时使用 `python scripts/render_conclusion.py <record.json>`，不要重新手写另一套结论。渲染器会先执行岗位校验，拒绝无效或伪造人工终态的记录。

## 单份简历

```markdown
### 初筛结论｜<候选人姓名或姓名未提供>（<candidate_id>）

| 项目 | 结论 |
|---|---|
| 候选人 | <姓名>（<candidate_id>） |
| 岗位 | 高级全栈工程师 |
| 三项筛选 | <学历、物流、高含金量项目的状态；不符合 N 项> |
| 语言参考 | <Go 已满足 / 转语言与学习交付成立 / 语言学习证据不足 / 待确认> |
| 模型建议 | <建议推进（待人工一审） / 进入二审（非最终） / 暂不推进（待人工一审）> |
| 核心判断 | <一到两句话，直接说明为什么> |
| 人工复核 | <一审待完成；二审不需要 / 二审待完成（模式与原因码）> |

匹配证据

- <维度>：<项目级事实>（<简历位置>）

关键缺口 / 待确认

- <明确写“未提供证据”“来源事实冲突”“有直接反证”或“待确认”，以及是否影响结论>

下一步

- <责任人需要执行的一个主动作>

面试优先验证

1. <优先级最高的问题>
```

单份结论卡后追加一行结论汇总，作为输出的最后一部分：

| 候选人姓名 | 候选人 ID | 岗位 | 模型建议 | 三项筛选 | 语言参考 | 核心判断 | 关键缺口/待确认 | 人工下一步 |
|---|---|---|---|---|---|---|---|---|
| `<姓名或姓名未提供>` | `<candidate_id>` | 高级全栈工程师 | `<建议状态>` | `<三项状态；不符合 N 项>` | `<Go / 转语言学习 / 未提供 / 待确认>` | `<一到两句>` | `<最关键一项；没有则写无>` | `<一个主动作>` |

规则：

- 匹配证据最多 3 条，先展示 Go 或物流放宽路径中的后端工程、BFF/微服务、数据与中间件和个人责任中的最强项目证据，再展示独立前端或高级工程结果；加分项不能挤掉后端核心项。前端低于 `E2` 时标明“后端偏重”，并展示针对性面试验证，不写成自动淘汰理由。
- 三项筛选必须单独展示学历、物流、高含金量项目状态及不符合数量。语言参考可显示“Go 已满足”“转语言/转栈学习交付成立”“简历未提供”或“待确认”，但不得计入淘汰数量。
- 关键缺口/待确认最多 3 条；没有时写“无影响当前建议的关键缺口”，不得把 `not_evidenced` 写成“不具备”。只有 `directly_not_met` 可表述为“简历明确陈述不满足”，`conflicting` 必须表述为“来源事实冲突、待二审”。
- 同一个决策相关不确定项只显示一次；详细审计记录保留完整原因码，结论卡只显示 `U01`–`U10` 短码。
- 默认只展示优先级最高的 3 个面试问题；完整审计记录可以保留最多 5 个。
- 下一步只写一个当前可执行的主动作。`second_review` 必须写明模式和原因码；来源/事实确认与盲审要明确区分。
- 结尾加一句：“以上为非最终初筛建议，须由招聘责任人确认。”
- skill 原始记录不输出模型自拟总分。应用层可以在结构校验后展示版本化的确定性证据匹配分与 A–E 档，但不得输出候选人强制排名、单独的“通过/淘汰”字样或大段 JD 复述。
- 姓名仅用于展示和人工核对，不得成为证据、缺口或建议依据；必须同时显示稳定的候选人 ID。姓名未在简历中明确给出时写“姓名未提供”，不得猜测。

建议状态映射：

| 机器状态 | 招聘者展示 |
|---|---|
| `advance_pending_human` | 建议推进（待人工一审） |
| `second_review` | 进入二审（非最终） |
| `do_not_advance_pending_human` | 暂不推进（待人工一审） |

维度展示名：经验与全栈职责、后端工程能力、BFF/微服务、前端独立交付、数据与中间件、AI 工程化、物流领域、重构/高级工程深度、行政条件。

## 批量简历

先给一张表，每位候选人一行：

表前显示岗位、rubric 版本、总数，以及建议推进/二审/暂不推进的数量。统计仅用于组织人工队列，不代表排名。

| 候选人姓名 | 候选人 ID | 模型建议 | 主栈优先级 | 优先信号 | 核心判断 | 最强证据 | 关键缺口/待确认 | 二审 | 人工下一步 |
|---|---|---|---|---|---|---|---|---|---|

每个单元格只保留一个最重要信息；多个短要点用 `<br>` 分隔。按输入顺序展示，表后只展开 `second_review` 或用户点名候选人的单份结论卡；不自动排名。

可以将多份记录作为多个参数传给渲染器，也可以传入包含记录数组的 JSON 文件：`python scripts/render_conclusion.py <record-1.json> <record-2.json>`。
