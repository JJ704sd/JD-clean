# 高级全栈工程师岗位画像

- `role`: `senior-fullstack-engineer`
- `jd_version`: `senior-fullstack-2026-08-14-v1`
- `rubric_version`: `senior-fullstack-2026-09-01-v8`
- 招聘优先级：5/5
- HC：2
- 业务范围：跨境物流核心业务、BFF、微服务、Vue3 中后台和 AI 工程化

## 预期结果

候选人首先应能够使用 Go 承担应用服务、BFF/微服务与数据链路交付。岗位允许两种可推进画像：一是能够独立完成前后端模块的完整全栈；二是 Go 后端偏重、能与前端完成接口和业务闭环，并愿意补齐前端交付能力。Go 的项目级个人交付是主栈硬门槛；只有 Node.js、Java、Python、PHP 或其他后端栈不纳入本岗位。满足门槛后优先看个人责任边界、复杂业务交付、重构和物流/供应链经验。

## 正式 JD

### 核心要求

- 本科及以上、计算机相关专业，3 年以上应用研发经历；不再机械要求简历中已有 1 年独立前端职责。
- Go（包括但不限于 Gin/go-zero）生产项目个人交付经验，简历阶段至少达到 `E2`；Node.js、Java、Python、PHP 等其他栈不能替代。
- 微服务或 BFF 设计与开发经验。
- Vue3、TypeScript、Vite，中后台独立交付和组件化意识属于完整全栈强信号；后端偏重候选人可在技术面验证前端基础、协作边界和补齐意愿。
- MySQL/PostgreSQL、Redis、消息队列，以及数据模型和接口设计能力。
- 理解 LLM API、向量数据库和 RAG，能够与算法工程师协作落地。

### 高级强信号

- 系统重构、计算密集型场景优化、扩展性或稳定性建设。
- 明确的业务/技术约束、方案比较、取舍、生产结果和个人影响。
- 从需求、设计、前后端实现到上线运行的端到端责任。
- 可定位到个人负责的核心模块、关键决策或稳定性结果；仅列团队项目全貌不等于个人主导。

### 加分项

- 有可定位的系统或核心模块重构经验，并能说明重构对象、约束、个人动作和结果。
- 物流或供应链经验。
- 服务发现、熔断、限流等治理经验。
- Kubernetes 或 Docker Compose。
- 同时具备 Go 和 Node.js，或使用 Node.js 集成 AI；Node.js 仅作为补充能力。
- 与岗位相关的技术博客或开源贡献。

### 筛选优先顺序

1. 先应用 Go 硬门槛：没有至少 `E2` 的 Go 项目证据时暂不推进；若原文件解析、Go 项目事实或个人贡献不清，先二审。
2. 满足 Go 门槛后检查重构、架构、全栈交付和物流/供应链经验；物流经验是 15 分的强加分项，但不是硬门槛。
3. 区分完整全栈与 Go 后端偏重轨道。前端证据不足时生成技术面验证问题，不因该项单独淘汰；若近期经历明确以运维、可观测性、部署或技术支持为主且应用研发责任不清，按岗位方向二审。
4. Node.js 只作为补充能力展示，不替代 Go，也不与 Go 后端维度重复计分。

## 解释边界

- 框架和产品名是常见实现，不是唯一等价证据；等价性必须由项目上下文支撑。
- 技术原理和相邻栈经验可用于设计面试问题，但不能豁免 Go 主栈门槛；只有 Node.js、Java、Python、PHP 等经历不触发技术迁移二审。
- AI 经历属于重点验证维度，但单独未写不构成简历阶段淘汰条件。
- “未通过、已取消、未沟通”等流程状态不能直接作为能力标签；薪资、地点、到岗时间和求职意愿必须与能力判断分开。
- 缺口表中的“补充数据工程能力、支撑业务分析”与正式 JD 冲突，不纳入本岗位筛选。
