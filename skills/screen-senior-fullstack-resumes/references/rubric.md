# 高级全栈简历筛选 Rubric

- 当前版本：`senior-fullstack-2026-09-04-v11`

## 证据强度

| 级别 | 定义 |
|---|---|
| `E0` | 没有相关信息 |
| `E1` | 技能列表、自评、头衔、专业系统名或孤立关键词 |
| `E2` | 同一项目中有项目背景、个人动作、对象和责任边界 |
| `E3` | `E2` 基础上同时具备项目背景、个人动作、方法/取舍、结果口径和可核验影响 |

`not_evidenced` 不等于候选人不具备，但在三项简历主条件中，完整读取后仍为 `E0/E1` 的项目级要求记为 `not_met`。冲突或低置信度记为 `unclear` 并按反事实决定是否二审。

## 证据矩阵

| ID | 维度 | 足够证据 | 用途 |
|---|---|---|---|
| `SEN-EXP-01` | 应用研发经历 | 日期、应用研发职责和近期主线至少 `E2` | 排序/追问 |
| `SEN-BE-01` | 后端语言、转语言与学习交付 | Go 项目个人交付，或转语言/转栈后完成真实后端交付，至少 `E2` | 非阻断参考/追问 |
| `SEN-ARCH-01` | 微服务/BFF | 服务边界、接口、拆分或架构责任至少 `E2` | 排序/追问 |
| `SEN-FE-01` | 前端交付与协作 | 页面、组件、状态或工程化个人交付至少 `E2` | 排序/追问 |
| `SEN-DATA-01` | 数据与中间件 | 数据模型、查询、缓存、异步或一致性动作至少 `E2` | 排序/追问 |
| `SEN-AI-01` | AI/RAG 工程化 | LLM、向量检索、RAG 或算法协作项目证据 | 排序/追问 |
| `SEN-DOMAIN-01` | 物流/供应链 | WMS、TMS/VMS、ERP/OMS、仓储、运输、订单、履约、轨迹、计费、路由或时效项目个人交付至少 `E2` | 三项主条件 |
| `SEN-LEVEL-01` | 高含金量项目 | 有个人参与，且业务量、使用量/覆盖、参与程度、业务复杂度中至少两类有可信事实，至少 `E2` | 三项主条件 |
| `SEN-ADM-01` | 学历/专业 | 明确本科及以上且专业满足要求，`E1` 即可 | 三项主条件 |

专业系统缩写仅用于扩大召回：WMS、TMS/VMS、ERP、OMS、CRM 等单独出现最多 `E1`。CRM/通用 ERP 只有在物流上下文明确时才支持 `SEN-DOMAIN-01`，否则可用于评估 `SEN-LEVEL-01`。

## 三项计数

`priority_profile.qualification_dimensions` 固定包含：

- `education`：`SEN-ADM-01 >= E1` 为 `met`；
- `logistics`：`SEN-DOMAIN-01 >= E2` 为 `met`；
- `valuable_project`：`SEN-LEVEL-01 >= E2` 为 `met`。

冲突或低置信度为 `unclear`，其余为 `not_met`。`unmet_requirement_count` 只统计 `not_met`：

- 0–1 项：`advance_pending_human`；
- 2–3 项：`do_not_advance_pending_human`；
- 存在会改变阈值的 `unclear`：`second_review`。

学历满足但物流为 `not_met` 时，只要高含金量项目为 `met`，必须保留推进资格。`language_learning_signal` 单独记录 `supported`、`not_evidenced` 或 `unclear`，不计入 `unmet_requirement_count`，也不单独触发二审或暂不推进。

## 确定性评分

评分仅表达 9 个证据维度的覆盖程度，继续使用 `E0=0%`、`E1=40%`、`E2=75%`、`E3=100%` 和既有权重。分数与 A–E 档不得替代三项计数、建议状态或人工复核。

## 二审与负面边界

- 解析不可靠、学历事实冲突、物流归属或高含金量项目个人参与的澄清会改变计数时进入二审。语言迁移或学习交付证据不清只进入面试追问。
- 只要现有确定项已经无论如何达到 2 项不符合，无关疑点不应制造形式化二审；安全类 `U11` 除外。
- `directly_not_met` 仅用于有可定位明确反证，不能由“未写”推断。简历未提供足够证据时使用 `not_evidenced`，再由三项主条件映射为 `not_met`。
- 负面建议仍须人工一审确认；不得自动拒绝。
