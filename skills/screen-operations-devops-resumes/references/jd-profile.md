## 工作目标

候选人需能在容器与虚拟机混合环境中，承担业务系统和 AI 产品的运维交付与稳定性工作：交付环境和资源，维护基础服务与发布链路，建立可观测和事故闭环，并治理模型、RAG、Agent 的线上运行与成本。

## 能力范围

1. 环境与资源生命周期：资源开通、扩缩容、回收、环境一致性和独立环境交付。
2. 基础服务和云迁移：PostgreSQL、Redis、消息队列的部署、迁移、备份恢复、容量和版本管理；使用阿里云或可迁移的同类云服务。
3. 容器与交付：Docker、Docker Compose；构建、测试、部署、回滚、变更审批与发布记录。
4. Linux 与网络：CPU、内存、磁盘、连接数等线上问题的定位和处置。
5. 稳定性：监控、日志、告警、巡检、SLO 口径、响应分级、故障复盘与闭环。
6. AI 应用运维：模型 API/网关配额、限流、供应商切换、密钥轮换；向量检索、RAG、Agent 运行链路的可观测和线上回归。
7. AI 成本与变更治理：Token 用量台账；模型及 Prompt 版本的灰度、对比、效果验证和回滚。
8. 安全和灾备：主机基线、凭据和最小权限、生产审计、备份策略与恢复演练。
9. 自动化和成本：Shell 与 Python 或 Go 脚本、IaC/配置管理、自助化、资源台账和升降配建议。
10. 协作交付：与研发、测试、算法、产品协作，维护运行文档和复盘。
11. 项目规模加分：有可核验的高运维复杂度、业务量、用户量、交易量或峰值负载经验，并能说明本人参与的运维职责。
12. 公司电脑与办公 IT：设备资产台账、发放配置回收、Windows/macOS 与办公软件安装升级、故障排查、数据备份恢复、系统重装和入离职设备交接。
13. 办公网络与 VPN：有线/无线网络与 VPN 的搭建配置维护、远程接入账号权限、连接/访问/性能问题排查和安全验证。
14. 行业背景加分：物流、供应链或跨境业务经验，需有明确业务事实并能与本人系统/平台工作关联。

## 替代经验和非门槛

- 云厂商可以是阿里云或同类平台。云上同类托管服务的运维经验可迁移；不得只因未写阿里云品牌而降低能力判断。
- CI/CD 工具按 Gitea Actions、GitLab CI、Jenkins 任一或具有可比能力的流水线取证；不要求同时掌握多个产品。
- 消息队列可以是与岗位场景相符的实际队列产品；需证明个人的运维、恢复或故障处置动作。
- Prometheus、Grafana、Loki 是示例。具备告警闭环的同类监控、日志和云监控方案均可接受。
- Ansible、Terraform 属加分实践示例，不是默认硬门槛。Kubernetes 与服务网格不是必需项；缺失不得扣为岗位不匹配。
- 物流、供应链或跨境经历是加分项。缺失不能成为拒绝理由；公司名称或客户名称不能替代明确行业事实。
- 高复杂度、大业务量或大用户量项目属于加分项。按系统依赖、统计周期、业务量/用户量/峰值等可核验证据判断，并确认候选人本人参与项目运维；不设跨业务统一的绝对数值门槛。
- “团队与愿景”用于理解业务背景；口号、行业热情或 AI 原生表态本身不构成能力证据。
