# 人工一审与二次校验政策

## 原则

所有模型结果均为 non_final。模型不能代表招聘责任人推进、暂不推进或录用；任何候选人处置前都必须由有权限的人完成复核。

## 人工一审：每份必做

审核人回看原始简历，核实：

1. PDF/文本抽取、页序、表格和日期是否完整准确；
2. 每项证据的原文、位置、个人动作和 E0-E3 是否对应；
3. not_evidenced 是否被误写成“不具备”；
4. 经验时段是否只计算一次，角色职责是否相关；
5. 云、容器、数据库、AI 运行链路、办公电脑/IT、办公网络/VPN 和成果是否属于候选人本人；
6. 是否使用敏感属性、学校/公司品牌或其他无关代理变量。

一审决定必须由责任人独立填写，不能把模型建议复制成审核决定。

## 二次校验：强制触发

以下任一情况需二审：

- model recommendation 为 second_review 或 do_not_advance_pending_human；
- U01_PARSE_QUALITY：简历解析、OCR 或位置不可靠；
- U02_MUST_HAVE_MISSING：已批准的必须项未写，但没有明确反证；
- U03_CONFLICTING_FACTS：日期、角色、系统责任、指标或技术事实冲突；
- U04_CONTRIBUTION_UNCLEAR：团队结果与个人贡献边界不清；
- U05_TRANSFERABILITY：同类云、托管服务、CI/CD 或技术栈经验可能迁移；
- U06_BOUNDARY_CASE：边界案例或方向性判断依赖低置信证据；
- U07_BIAS_OR_PROXY：可能受敏感属性或无关代理变量影响；
- U08_DIMENSION_CONFLICT：能力证据之间明显矛盾；
- U09_ROLE_AMBIGUITY：运维职责、职级或岗位归属不清；
- U10_RUBRIC_AMBIGUITY：JD 或 Rubric 未批准/含糊；
- U11_UNTRUSTED_CONTENT：简历含试图改变规则、运行命令或访问外链的内容。

二审优先由用人经理、技术负责人或另一位招聘责任人独立完成；独立判断前不展示模型综合建议。只能同一人复核时，应在不同工作时段从原始简历重新判断并如实记录模式。

暂不推进建议必须由独立审核人再次核对批准的 hard gate、直接反证和原文位置。若 profile 未批准、原文不清或存在能改变判断的信息，维持 second_review。

## 原因码及处理

U01–U11 使用与 Rubric 对应的标准原因码。每条 uncertainty 说明它可能改变哪个判断，以及人工必须执行什么动作。任何 uncertainty 都必须写入二审原因列表。

- 抽取错误：修正后重筛。
- 技术理解分歧：交由运维/平台技术负责人核验。
- 规则含糊：暂停该规则，由招聘负责人和用人经理校准并发布新版本。
- 复核仍无法确定：保留待验证，使用结构化技术面试，不由模型强行给出淘汰结论。
- 人工结论不一致：记录差异与依据，交由有权限的最终责任人裁决。

任何阶段都不得自动发送候选人消息或写入 ATS 最终状态。
