# 招聘者结论卡格式

默认输出结论卡、岗位证据矩阵、最多 3 条最强匹配、最多 3 条关键缺口、一个人工下一步和 3–6 个针对性面试问题。不要首先倾倒完整 JSON。

供招聘团队内部复核的单份结论卡应包含当前 Rubric 的证据覆盖总分、档位和 20 项权重/得分明细（其中外包/派遣信号为零权重）。评分卡由 `score_screening_record.py` 确定性计算；分数不是推荐阈值，也不得用来替代 hard gate 或人工审核。对外候选人名单、分享版复核清单和飞书文档不展示具体分数、单项得分或数字排名。历史 v1/v2/v3/v4/v5 记录不生成追溯分数。

## 批量简历

表前写明岗位、JD/rubric 版本和输入数量；按输入顺序一人一行，不按分数或背景排名。

| 候选人 | ID | 建议 | 最强证据 | 关键缺口/待确认 | 二审 | 人工下一步 |
|---|---|---|---|---|---|---|

manual_review、parse failure、模型输出无效等属于流程或复核状态，不是候选人能力结论。不得隐去二审记录，也不得因名额限制从批次中自动淘汰候选人。

## 表达规则

- 不使用“通过”“淘汰”“录用”等最终措辞。
- 只把明确原文说成事实；不得将未提供写成不具备。
- 姓名只用于展示和人工核对；证据、缺口与建议在忽略姓名后仍须成立。
- 不输出模型自拟总分或候选人强制排名；只使用 Python 确定性生成的内审证据覆盖分。
