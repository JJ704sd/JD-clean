# 项目改写与技术核对

以下案例完全虚构，仅演示从给定事实到可靠表述的转换，不能直接当作用户经历。数字、技术栈和职责只采用当前用户材料。

## 后端项目：没有数字也可以写清楚

原句：“熟悉后端，参与管理系统开发，提升系统稳定性。”

给定事实：课程团队项目；本人用 Node.js 实现预约创建和列表接口；SQLite 持久化；拒绝同一账号重复预约；完成本地接口测试；没有性能测量或真实用户。

可用改句：“在课程预约系统中负责 Node.js 预约接口与 SQLite 数据持久化，实现参数校验和同账号重复预约拦截，完成正常预约、重复提交及无效参数的本地接口测试。”

不能增加“高并发、微服务架构、线上稳定运行、效率提升 80%”。如果重复预约的实现机制没有材料，不自行写成分布式锁或唯一索引。

## 前端为主：联调贡献不扩大成后端所有权

原句：“独立完成全栈商城，负责前后端开发。”

给定事实：本人实现 Vue 商品列表、筛选和购物车页面，并与队友提供的后端接口联调；后端由队友完成；本人处理加载失败和空列表状态。

可用改句：“负责团队商城的 Vue 商品列表、筛选与购物车页面，完成后端接口联调及加载失败、空列表状态处理；后端服务由队友负责。”

后端实践不足放在补强建议中，不替换成“自主搭建全栈架构”。

## AI 项目：结构校验与业务可靠性分开

原句：“搭建智能问答系统，彻底消除幻觉，准确率 100%。”

给定事实：本人调用模型 API，对返回 JSON 做字段检查；异常时返回人工处理提示；测试过少量样例；没有检索模块、语义正确率评测或线上使用证据。

可用改句：“实现模型 API 调用与 JSON 字段校验，针对响应缺字段或格式异常返回人工处理提示，并用本地样例验证正常与异常路径。”

不能写成 RAG、多 Agent、语义正确率提升或消除幻觉。若只有使用 AI 编程助手生成代码，说明本人审查、修改与测试的实际工作，不称为模型平台研发。

## 数字与成果的口径

强指标进入成稿前确认：

- **来源**：测试报告、监控截图、业务报表或本人明确提供的测量记录。
- **环境**：本地测试、预发、演示或生产；不要把压测写成真实流量。
- **统计**：数据量、请求数、并发、时间窗口及平均值/P95/P99。
- **对比**：前后使用同一输入、环境和统计方法；保留单位。
- **归属**：指标对应本人模块还是团队整体，以及本人做了哪项动作。

材料没有这些信息时，不选择更好看的数字。保留已有数字为待确认，成稿改用有材料支持的具体结果；不能把无指标自动写成“显著提升”。

“从 800 ms 到 200 ms”的耗时下降与吞吐增长不是同一指标；不能用百分比替换时偷换分母。以有限样本观测到未丢失、未超卖，只能写明样本和范围，不能推广成永不丢失或绝对可靠。

团队商业客户、获奖、访问量和营收可作为项目背景，但不能自动成为个人创造的成果。尚未合并的 PR 写提交/协作状态，合并与发布时间只在实际确认后采用。

## 技术表达的易错点

技术核验不确定时查对应官方文档或用户代码，未经核实的因果关系留待确认：

- 数据库约束、幂等键、乐观锁和分布式锁各自解决什么问题；使用某工具不直接证明并发安全。
- 消息入队、生产者确认、消费确认、业务落库和外部接收完成分层描述；超限丢弃不能支持消息零丢失。
- JSON Schema 约束格式，不直接证明内容真实、语义正确或没有幻觉。
- MySQL 的预计算汇总表不要直接写成数据库原生物化视图，除非确有相应实现与技术依据。
- 哈希校验与加密不同；采用加密也不能直接证明传输链路安全。
- RAG 说明实际实现的分块、检索、排序、引用或评测环节；没有检索集与口径不写召回率。
- Redis、数据库、消息队列和外部接口的状态一致性需要实际处理与验证，不能仅由“加了重试”推导。

只在事实支持时使用“主导、独立、核心、0 到 1”。已有夸大或技术矛盾先标明并缩回可支持范围，不用更专业的术语掩盖问题。
