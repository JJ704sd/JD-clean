# 岗位对齐与证据选择

用户当前 JD 是投递版本的依据。下表用于挑选可写事实，不是能力评分或淘汰规则。在 JD-clean 中可按需读取仓库现有岗位画像 `skills/screen-fullstack-intern-resumes/references/jd-profile.md` 和 Rubric；独立使用本 Skill 时不依赖这些文件。

## 选什么内容

| 阅读者要知道什么 | 可写的实际证据 | 缺失时如何处理 |
|---|---|---|
| 会用一种后端语言完成开发 | 本人实现的接口、服务逻辑、脚本或持久化模块 | 列语言基础；安排具体后端实践，不把课程名升级成项目 |
| 理解 HTTP 和接口联调 | 参数校验、错误响应、鉴权、分页、请求/响应和联调问题 | 用已有联调贡献；不自动声称负责后端接口设计 |
| 做过数据处理 | 表关系、SQL、事务、索引、导入导出或缓存中的个人实现 | 只保留已学或已做部分；没有 Redis 不补造 |
| 具备前端基础 | 页面、组件、表单校验、状态管理、接口状态和异常提示 | 后端为主也可写真实页面工作；缺失时列为实践计划 |
| 能把事情完成 | 需求、实现、调试、测试、部署、文档中的闭环证据 | 课程与个人项目有效，不要求生产客户或正式实习 |
| 有 AI 学习或实践 | LLM API 接入、检索、引用、工具调用、错误处理或学习行动 | AI 编程工具使用与 AI 应用开发分开；学习计划不写已实现 |
| 能满足实习安排 | 本人明确提供的在读状态、每周天数、到岗时间、持续时长 | 缺失就确认；不能由毕业年份、年龄或学校推断 |
| 符合业务方向 | 本人做过的订单、库存、履约、电商等领域逻辑 | 作为相关性信号，不给无关项目强行贴物流标签 |

仓库现有实习岗位偏好后端实现，接受 Go、Node.js、Java、Python 任一后端基础，Vue3/TypeScript 和 AI 工程是优先或培养方向。该偏好不能自动推广到所有全栈实习 JD。没有正式实习、名校背景或大规模线上服务，不妨碍写出可靠的实习简历。

## 排序与篇幅

教育和明确的实习安排放在容易找到的位置。实际开发实习相关且个人贡献明确时优先；课程/个人项目更有证据时，可让最强项目先于弱实习。保留最强的 1–3 段，而不是给所有经历平均篇幅。

每段经历选择 2–4 条互不重复的个人动作，优先接口与数据实现、一个有解释价值的难点，以及实际验证结果。前端为主时可突出一个完整页面到接口的链路；不要因为目标写“全栈”就把团队后端归给本人。

技术熟悉程度应能通过代码、调试记录或口头追问说明。“熟悉”不是工具名数量；删除重复关键词比增加中间件更有用。

## 补强任务与面试可讲性

只针对当前缺口提出任务。例如：

- **后端缺口**：给现有页面实现一个带校验、分页和持久化的接口，保留接口文档、提交及正常/异常测试结果。
- **数据缺口**：为本人现有项目解释表关系并实现一个真实查询，保留 SQL、执行计划和验证数据规模。
- **AI 缺口**：给已有应用接入一个可解释的模型能力，保留超时/异常处理与输入输出样例；无需直接上多 Agent。
- **工程缺口**：为现有功能补测试或部署说明，留下可复现命令与结果。

这些都是计划。完成并由用户提供事实后，才能改写为经历。每个最终项目要点至少能回答“我改了哪里、为什么这样做、怎样确认有效、还有什么限制”。
